## Unverified / risks
- RISK-010 (M9, owner action) Desktop shell parts that are **not verified on macOS/Windows**: native menu bar, tray icon, global shortcuts, dock badge/taskbar progress (`HostCommand::Badge/Progress`: badge macOS only, progress via tao), context menus on Windows/Linux (only macOS popup is wired), `app.autostart` (LaunchAgent/registry/.desktop writers), file-association/URL-scheme registration (Info.plist keys generated; Windows `register.reg` needs the install path edited), `rfd`/`notify-rust`/`arboard` backends. Linux (webkit2gtk under Xvfb) runs the IPC/files/store/server smoke test in CI; Windows `cargo check` of the shell passes, macOS cannot be checked here. CI runs `tools/player-smoke.mjs` on macOS/Windows as non-blocking steps. Wayland: tray/global shortcuts compositor-dependent.
- RISK-011 (M9) Permission manifest = application-level guard, not an OS sandbox (no App Sandbox/security-scoped bookmarks yet: `picked` paths are only remembered for the current run). Dialogs/`process.run`/`http.fetch` run on the UI thread in the native player (a slow call blocks the window; the page itself is not blocked). `dialog.open` in the browser fallback copies the chosen file into virtual app data. Clipboard images are unsupported natively. Markdown code fences are not syntax-highlighted in the code editor (CodeMirror `codeLanguages` not in the vendored bundle).
- RISK-012 (M8) `./build.sh` for Windows has never been run (CI job `windows-latest` is non-blocking); macOS notarisation steps in docs/PACKAGING.md follow Apple's docs but are untested here.
- RISK-001a (M3-07 **owner action needed**) The `webview` feature compiles (type-checked against wry's Linux backend; the macOS build runs in CI `macos-14`) but embedding was never *run* on macOS. Checklist on the M1 Max: `./run.sh examples/conformance-2d` → (1) Scene tab shows the 2D view in the panel rect, (2) resize the window/split → view follows, (3) Retina scale correct (no 2× offset), (4) click inside the view then press W/E/R/Cmd+Z → editor reacts (keys are forwarded), click back in egui → shortcuts work, (5) open a menu / Cmd+K → the webview pauses (placeholder) and returns, (6) ▶ Play shows the game in the Game tab, Stop clears it. If anything is off use `./run.sh --no-webview` (Open in browser fallback; protocol identical). On Linux the webview is not wired (needs GTK loop) — macOS only for now.
- M3 editor verified here: egui_kittest (12 headless UI tests), Xvfb + software GL smoke run (splash → hub → project), Playwright for the viewport protocol/picking/drag/snap/gizmos/thumbnails/log bridge. Not verified: window-geometry restore (needs a window manager), drag-and-drop of OS files/asset→hierarchy with a real pointer, Retina rendering, IME input in the code editor (text is applied by our own key handler; composition events are left to egui).
- RISK-006 `nord-player` window shell (`--features shell`: wry+tao) cannot be compiled in the Linux sandbox (needs webkit2gtk/gtk); only its pure parts (`serve`, manifest, game-dir lookup) are unit-tested. macOS CI builds it and assembles `Playground 3D.app`; **owner must run a bundled game once** (window size, `nord://` module scripts, audio, Cmd+Ctrl+F). `bundle-mac` layout/plist/icns are tested on Linux; codesign/dmg only run on macOS.
- Export: `--optimize` is lossless PNG + WAV→MP3 only (no atlas packing / quantise → M4-11). Single-file builds keep UI fonts as sibling files. Vendored libs contain unused default CDN strings (Babylon); the offline check scans project-owned files + runtime only.
- Code editor limits: multi-cursor covers typing/delete/enter/tab/arrows only (no word-wise moves, comment toggle or auto-close with several cursors; undo clears extras), tokenizer is not a parser (regex literals / nested template strings can mis-colour), formatter = re-indent by bracket depth (+ JSON pretty-print), squiggles only for JS (`node --check`, needs Node on PATH) and JSON; Rust errors surface via the Console (`cargo check`) and are click-to-open. Ligatures are stored in the skin but not drawn (egui has no shaping).
- Viewport editing moves/rotates/scales the *first* selected entity only (multi-select is selection-only); parent rotation/scale are handled in 2D, 3D gizmos rely on Babylon's local/world handling (unparented entities verified).
- Model thumbnails need the 3D edit view to be connected (they are rendered there); in 2D projects models show an icon.
- `nord-serve` instances started by the editor keep running until the editor exits (one per opened project in a session).
- Examples opened from the hub are private copies under `~/.config/nord/examples/` (never edited in the engine repo).
- RISK-001 egui + wry child-webview embedding on macOS (z-order, keyboard focus, egui popups over the webview, HiDPI sizing) cannot be tested in the Linux sandbox; verify on macOS CI / M1 Max. Spike first (M3-07).
- RISK-002 Babylon Havok needs wasm served with `application/wasm`; some static hosts misconfigure → provide JS fallback (cannon-es) or inline base64 in single-file mode.
- RISK-003 `file://` loading blocks `fetch`/ES modules in browsers → single-file/file-safe export mode required (EXPORT_TARGETS).
- RISK-004 Vendored Babylon (and Phaser banner comments) contain default CDN/asset URLs (e.g. `cdn.babylonjs.com`, `assets.babylonjs.com`) used only when a feature is left unconfigured (VR button, blue-noise, loaders' default asset roots). `nord check-offline` flags them, so it is a gate for **project/build output** (M4 must set Babylon `Tools.*Url`/disable those paths and allowlist the rest), not for `vendor/`.
- M1 verified on Linux only: `nord serve` (incl. SSE reload endpoint wiring, HTML injection), `new`, `check`, `thumbs`, `check-offline`, `vendor --verify`. CI macos-14 job is untested until first push runs. SSE reload was not exercised in a real browser yet (M2 e2e). `rustup` wasm32 target is not installed in this sandbox (needed from M5).
- M2 core: `attachDom` and `virtualJoystick` (DOM code) have no tests yet — covered by the Playwright harness (M2-18). Prefab `overrides` format is: deep-merge onto the prefab root entity; an object with numeric keys patches an array by index (e.g. `{"scripts":{"0":{"attributes":{"speed":7}}}}`).  `Entity.worldPos` ignores parent rotation (backends handle rotation natively).
- M2 runtimes (verified headless Chromium/SwiftShader on Linux only; not yet on macOS/WKWebView or a real GPU): Phaser 4.2.1 arcade+matter, Babylon 9.30 + Havok. Notes: (a) Havok collision events only fire reliably when the *scene* steps physics, so Babylon physics uses Babylon's 60 Hz sub-step accumulator and results are copied back after each step (script `fixedUpdate` runs before it, in the same frame). (b) Havok `disablePreStep` is on by default — script-set transforms are pushed to the body for one step via `teleported()` and velocity is zeroed. (c) `isGrounded`/`raycast` `ignore` only skips the first hit (Havok returns the closest hit). (d) Phaser tilemaps are static world-space layers (not moved with their entity). (e) Phaser arcade bodies need entities without a rotated/scaled parent chain to be exact. (f) Hot reload does not re-fetch modules a script imports. (g) Software-GL e2e runs Babylon at ~4 fps so timings in tests are generous.
- M3-26 Game view (size presets, fullscreen, console strip) compiles and is wired through `game_tab()` in `app.rs`, but the real embedded webview behaviour (fullscreen toggle via `ViewportCommand::Fullscreen`, native view not covering the console strip) is **unverified on macOS** (RISK-001). The console strip is now laid out from a stored height *before* the webview is allocated, so overlap should be impossible by construction; if the console still hides behind the game, report it.
