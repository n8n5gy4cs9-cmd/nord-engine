API reference

Coming from Unity? Start with the Unity-style scripting API.

Use this section when you know what you want to do and need an exact name, signature or setting. For a first project, start with Getting started.

Components and project data#

Component index lists every built-in component. Each page includes fields, types, defaults, scene JSON, script handles and supported live changes. Project format explains the files these components live in.

Desktop and Rust#

Desktop API covers the typed JavaScript bridge, including files, dialogs, storage and windows. Rust API lists public Rust declarations, alongside the Rust guide.

Phaser and Babylon#

Engine API downloads provides separate ZIPs for Phaser 4.2.1 and Babylon.js 9.30.0, plus official online manuals and exact-version source links. Upstream API pages are available only inside those ZIPs; site search focuses on Nord.

For most game code, use Nord components and this.game services. The engine reference helps with escape-hatch objects and features that have no Nord wrapper. An upstream method is not automatically available as a Nord method.

For dummy developers

A signature tells you the inputs a function accepts. play(path, options) means give it a file path, and optionally settings. A return value is what the function gives back. If it returns a Promise, use await in an async function to wait for the result. Types describe values: number is a number; string is text; boolean is true or false.

Start with the Unity API for MonoBehaviour, Transform, maths, Input, physics, component wrappers and object lifetime. Use Public exports to verify an import. The component pages describe saved fields separately from runtime handles. Their field lists come from the editor schema; source-generated class pages describe Nord's implementation surface.

For dummy developers

A signature is a function's order form: supply the right items in the right places, and check what comes back. await means the result arrives later. A missing object may be null, so finding it and using it are two separate steps.

Choose a safe experiment#

Find the reference, copy the smallest complete example linked from it, and test one call. Do not paste an entire upstream engine class into an attached script. Phaser and Babylon downloads are references for native objects, not extra Nord methods.

Tiny challenge: predict the return value#

Before running a spawn example, say whether you expect an entity or a Promise. Then compare your answer with the object lifetime reference. Getting the answer right before executing the line is a useful superpower.

Components (34)
  • sprite — A single image (or one frame of a spritesheet) drawn at the entity position.
  • animatedSprite — A spritesheet with named animations. Animations are declared in the texture's `.meta.json` (`anims`).
  • text — World-space text (Phaser Text). For HUD text prefer `uiLabel`.
  • tilemap — A grid of tiles from a tileset image. Loads Tiled JSON (`.tmj`/`.json`) or Nord simple maps (`layers[].data`).
  • parallax — A screen-filling background layer that scrolls slower than the camera for depth.
  • particles — Particle emitter. 2D (Phaser emitter) and 3D (Babylon ParticleSystem) use the same component with tier-specific fields.
  • camera — 2D: configures the main camera (zoom, follow, bounds). 3D: creates a free (first-person) or orbit camera.
  • light — 2D: Phaser point light (turns on the light pipeline for all sprites). 3D: point / directional / spot / hemispheric light, optional shadows.
  • mesh — A primitive 3D shape (box, sphere, cylinder, capsule, torus, plane, ground).
  • model — A glTF/GLB model instanced into the scene, with its animations.
  • material — PBR (or unlit) material applied to the meshes of this entity.
  • skybox — Cube-map sky. `path` is a folder containing px/nx/py/ny/pz/nz.png (e.g. `assets/skybox/day`).
  • postProcess — Full-screen effects on the active camera: bloom, FXAA/MSAA, vignette, tone mapping, grain, sharpen, chromatic aberration.
  • rigidbody — Makes the entity a physics body. Add a `collider` for its shape.
  • collider — Collision shape. Without an explicit `size` it is taken from the sprite/mesh bounds.
  • joint — A Unity-style joint between this body and `connectedBody` (or the world): hinge, spring, distance, fixed, slider, wheel, target, relative, friction (2D, Matter) and hinge, fixed, spring, distance, ball (CharacterJoint), configurable (3D, Havok).
  • trigger — Shorthand for a collider with `trigger: true` — an invisible zone that fires `onTriggerEnter` / `onTriggerExit`.
  • lineRenderer — A poly-line drawn as a ribbon with a width and a colour gradient (Unity's LineRenderer).
  • trailRenderer — Leaves a fading trail behind a moving entity (Unity's TrailRenderer).
  • spriteMask — Shows or hides sprites inside its shape (Unity's SpriteMask).
  • spriteShape — A filled shape with an edge line from a list of points (Unity's SpriteShape: hills, platforms, pools).
  • shadertoy — Runs a shader written for shadertoy.com (GLSL ES 3.00 `mainImage`) as a picture in the scene or on a mesh.
  • audioSource — Plays a clip from an entity. Use `bus` to route it (sfx | music | ui).
  • audioListener — Marker for the entity that "hears" the game. Currently a no-op placeholder (audio is not spatialised yet).
  • uiPanel — A background box in the DOM UI layer.
  • uiLabel — Text in the DOM UI layer.
  • uiImage — An image in the DOM UI layer.
  • uiBar — A progress bar (0..1).
  • uiButton — A clickable button. Emits `click` on the entity, calls `onClick()` on its scripts and, if `event` is set, `game.events.emit(event)`.
  • path — A list of waypoints that can be sampled by distance — for patrols, moving platforms, camera rails.
  • spawner — Spawns a prefab every `interval` seconds at the entity (plus `offset` and random `jitter`), keeping at most `max` alive.
  • graph — Runs a visual-scripting graph file (`graphs/*.graph.json`) on this entity. *This entity* in the graph is the owner. Built in the Graph tab.
  • animator — Unity-style state machine (`anim/*.animator.json`) that switches the clip of the `animatedSprite` (or the glTF animation of the `model`) on the same entity from parameters (float, int, bool, trigger). Built in the Animator tab; see the Animator chapter.
  • netSync — Multiplayer: the owning peer sends this entity's position (and optionally rotation, scale and chosen `vars`) to everyone else, who see it move smoothly. Owner = the player given to `net.spawn`, otherwise the host. Needs `game.net` connected; see the Multiplayer chapter.
