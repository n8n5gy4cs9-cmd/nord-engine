Manual — choose a task

The Manual explains how Nord's features work. Each chapter is a task reference. Tutorials teach a whole project in order; Examples provide reusable code; Cheatsheets help you recall an exact operation.

For dummy developers

You do not need to read this site from beginning to end. First make one object appear, then make it move, then give it a rule. Add another system only when your game needs it.

Before you start#

Open a project from the project hub. Save your changes before pressing Play. Start with Getting started if the editor is new to you.

Write gameplay in the Unity style#

Read Unity-style scripting, then keep the Unity API beside your code. Nord uses JavaScript with Unity names. It implements a documented subset of Unity behavior; check coverage before porting an unfamiliar feature.

Use the Examples sidebar's Unity API · map and recipes group for maths, input, physics, renderers and lifecycle. Existing tutorials can use the native lower-case NordScript lifecycle. Follow their code consistently within each script.

Test and publish#

Read Debugger when behavior differs from your expectation, Performance when it is slow, and Export when you are ready to share. An exported static game and a saved editable project serve different purposes: keep the project as your source.

Separate authoring, testing and shipping#

  1. Author: stop Play, select the object, change its Inspector settings or file, and save. The project folder stores your source.
  2. Test: press Play and verify one expected result. Inspect the Console first when it differs. Live scene edits are temporary.
  3. Ship: export a separate playable output and test that output too. A game that works in the editor still needs its asset paths and hosting checked.
For dummy developers

A prefab is a reusable object recipe. The scene contains instances of that recipe. Changing one live instance while playing does not rewrite the saved recipe. Think cookie cutter, cookies, and a very temporary taste test.

Try a tiny challenge#

Build a room with one light, one movable object and one button. Give the button a visible purpose before adding decoration. Use the relevant feature chapter when you reach that part; this is a navigation exercise, not a speedrun.

2D and 3D worlds (9)

Gameplay, sound and interfaces (12)
  • Audio — Sound effects, music, buses, autoplay rules.
  • UI & HUD — DOM HUD, menus, themes and skins, touch controls, 3D labels.
  • Input — Actions, keyboard, mouse, touch, gamepad, rebinding.
  • Event sheets — Build game logic without code — conditions, actions, picking, triggers, loops, variables and functions, the Construct way.
  • Behaviors — Attach ready-made movement and gameplay (Platform, 8-Direction, Bullet, Sine, Turret, Pathfinding…) to any entity.
  • Effects, particles and timelines — Blur, glow, vignette and colour effects; a particle editor with live preview; keyframe timelines with easing.
  • Addons, data objects and languages — Extend event sheets with your own plugins, keep data in Array/Dictionary/JSON objects, and translate your game.
  • UI Designer — Build menus, HUDs and dialogs visually. Layout, text, images and 9-slice, skins, input fields, and how a button reaches your code.
  • Node graphs (visual scripting) — Make gameplay by connecting nodes: events, flow, math, entities, input, UI, audio and scenes. No code needed, and an escape hatch to any code when you need it.
  • Animator — A Unity-style state machine for sprite animation. Parameters, states, transitions with conditions, Any State, live testing.
  • Multiplayer — Host and join a room, send messages, call functions on other players (RPC), spawn and sync entities, and test with fake lag. Peer to peer, no server.
  • In-game Dev Console — Drop one prefab into your game and get a command console with cheats, autocomplete and your own commands. Add commands with one line of code.
Test and publish (8)
  • Rust / WASM — Rust game runtime (macroquad + rapier) and Rust apps (egui), building and limits.
  • Export & hosting — Static web builds, single-file, Mac app, hosting recipes, offline guarantee.
  • Performance & debugging — Profiling, pooling, texture and physics budgets.
  • Find an API or file setting — Choose the Unity API, native Nord API, component fields or file reference for the task in front of you.
  • Desktop apps — Real native apps — files, dialogs, notifications, tray, menus, storage, a local web server — from the same project, in JS or Rust.
  • Debugger and profiler — Pause, step, breakpoints on events, live instance editing, an expression console and a frame profiler — in any running game.
  • Preview, history and project tools — Test on your phone, undo a bad afternoon with version history, rename safely, and export an installable web app.
  • Run the editor in a browser or on a server — The same Nord editor in a browser tab (no install, projects stay in your browser) or on your own Linux server for you and your team.

Check yourself#

  • You can name the object and component you are changing.
  • You know whether you need a concept explanation, a guided tutorial, a code example or an exact API signature.
  • You can reproduce the result after saving and pressing Play.
