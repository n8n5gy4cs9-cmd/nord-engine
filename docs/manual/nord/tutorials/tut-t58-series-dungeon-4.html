T58 Nord Dungeon 4: Coins and score

Part 4 of the native-scripting dungeon series, continuing from part 3, camera and a bigger level. Allow 40 minutes.

What you will build: twelve coins hidden in the dungeon, a counter on the screen, and a "You found all the coins!" message with Press E to play again.

2 Triggers#

A trigger is a collider that does not block anything but tells you when something enters it. A coin is exactly that: the hero walks through it and we want a message. In the data of a coin the collider says trigger: true:

{ type: 'rigidbody', mode: 'static' }, { type: 'collider', shape: 'box', size: [16, 16], trigger: true },

The script on the coin gets onTriggerEnter(other) called with the entity that came in:

import { NordScript } from 'nord';

export default class Coin extends NordScript {
  start() {
    this.y0 = this.entity.pos[1];
    this.t = this.rng.range(0, 6);                                  // every coin bobs out of step with the others
    this.taken = false;
  }

  update(dt) {
    this.t += dt;
    const p = this.entity.pos;
    this.entity.pos = [p[0], this.y0 + Math.sin(this.t * 4) * 2, p[2]];
  }

  onTriggerEnter(other) {
    if (this.taken || !other.hasTag('hero')) return;
    this.taken = true;                                              // destroy() is deferred to the end of the frame
    this.events.emit('coin');
    this.entity.destroy();
  }
}
  • other.hasTag('hero') ignores everything but the hero. Tags are strings on an entity: the hero got the tag hero in part 1, walls get solid, coins coin. They are how scripts recognise things without knowing their names.
  • this.rng.range(0, 6) is the game's random number generator. We start each coin's bobbing at a different time, so they do not move in lockstep. Math.random() would also work, but this.rng is seedable, which matters when you want a replay or a daily challenge to be identical.
  • this.entity.destroy() removes the coin at the end of the frame, not immediately; taken stops a second overlap in the same frame from counting twice.

Why does the script emit an event instead of changing a score variable directly? The coin does not know that a HUD, an achievement system or a sound effect exists. It only announces "a coin was taken". Anything interested subscribes. That keeps every script small and lets you add features later without opening old files.

4 The HUD#

A HUD is a screen layer on top of the game, made of HTML elements that the engine creates for you. this.ui.label(text, options) makes a text label, screen: 'hud' puts it on the always-visible layer, x/y are in pixels from the top-left and anchor picks another corner or 'c' for the centre.

Create an empty entity Hud and the script scripts/hud.js:

import { NordScript } from 'nord';

export default class Hud extends NordScript {
  start() {
    this.count = 0;
    this.total = 0;
    this.score = this.ui.label('', { screen: 'hud', x: 12, y: 8, size: 22, color: '#ebcb8b' });
    this.offs = [
      this.events.on('level', ({ coins }) => { this.total = coins; this.refresh(); }),
      this.events.on('coin', () => { this.count++; this.refresh(); }),
    ];
    this.refresh();
  }

  refresh() {
    this.score.set(`● ${this.count} / ${this.total}`);
    if (this.total > 0 && this.count === this.total) this.win();
  }

  win() {
    this.ui.label('You found all the coins!', { screen: 'hud', anchor: 'c', size: 34, color: '#a3be8c' });
    this.ui.label('Press E to play again', { screen: 'hud', anchor: 'c', y: 44, size: 20 });
    this.won = true;
  }

  update() {
    if (this.won && this.input.pressed('interact')) this.game.restart();
  }

  onDestroy() { this.score?.remove(); this.offs?.forEach((off) => off()); }
}
  • The HUD owns the counting. It listens to level (to learn the total) and coin (to count). The coin script and the level script know nothing about it.
  • this.score.set(text) replaces the label's text.
  • win() makes two labels. anchor: 'c' centres them on the screen and y: 44 pushes the second one 44 pixels down from the centre.
  • this.input.pressed('interact') is true for exactly one frame when the key goes down. The default project maps interact to E and Enter. this.game.restart() throws the scene away and builds it again from the saved scene file: every coin returns.
  • onDestroy removes the label and unsubscribes. When you restart, scripts are destroyed and recreated; a script that forgets to clean up leaves a ghost label and a ghost listener behind.

Why is finish called from refresh? The check "have we got all of them" belongs where the counting happens. In the next part, a death will call the same kind of function.

Press Play. Collect the coins: the counter increases and the coin disappears. Take the last one and the message appears. Press E: the level resets.

5 Check yourself#

  • The counter starts at ● 0 / 12 (the total comes from the level, not a typed number: add a coin to the map and it says 13).
  • Walk through a coin diagonally against a wall corner: it still counts.
  • In the Console there are no errors while restarting five times in a row.

If the counter shows 0 / 0, the HUD started after the level announced itself: check that Level is above Hud in the Hierarchy, or make the HUD ask the level for the total in start.

What you learned#

  • A trigger collider reports overlaps with onTriggerEnter without blocking.
  • Tags let scripts recognise what they touch.
  • Events (events.emit / events.on) keep scripts independent.
  • this.ui makes HUD labels; always remove them in onDestroy.
  • game.restart() rebuilds a scene.
