T37 Orbital Salvage — code Rust gameplay and export real WASM

Build Orbital Salvage, a Rust arcade game that runs in a browser through WebAssembly. Fly through bouncing asteroids, collect ten gold cargo cores and preserve three hull points before sixty seconds expires. Space performs a short dash with a brief shield and a two-second cooldown. Cores add two seconds; P pauses; R restarts.

You will separate the game rules from rendering, write deterministic tests, use macroquad through Nord's Rust runtime dependency, then build an actual .wasm web game. This is compiled Rust, not JavaScript with a WASM-labelled button.

Allow two hours plus first-build time. You need Rust/Cargo and the wasm32 target. No npm packages or wasm-bindgen CLI are needed for this macroquad game. Download the complete Rust source project. No external art/audio files are needed: the renderer draws original geometric shapes.

1. Set up a Rust project Nord can build#

Extract the project to a writable folder, then open nord.project.json in Nord. Its type is wasm-game. Unlike a JS scene game, this sample uses a direct macroquad loop; the scene hierarchy does not author its procedural arena. Nord provides the project, code editor, build, Console and export workflow.

The project contains Cargo.toml, Cargo.lock, src/main.rs, src/sim.rs and a dev index.html. Inspect the dependency:

[dependencies]
nord-runtime-wasm = { path = "../../crates/nord-runtime-wasm" }

[workspace]

That relative path is correct inside the engine's examples/rust-salvage folder. If you extract elsewhere, change it to your engine checkout's absolute crates/nord-runtime-wasm directory. Nord-created Rust project copies normally rewrite this path; a manually extracted zip cannot infer your engine's location. Keep the empty workspace section so the project is its own Cargo workspace.

Install the target if it is absent:

rustup target add wasm32-unknown-unknown

The first Cargo build may fetch pinned crates. Later builds can use the local cache. Offline operation of the exported game does not mean Cargo can compile an uncached dependency without first obtaining it. The supplied Cargo.lock pins the resolved versions used for this sample.

Checkpoint: Cargo.toml points at an existing engine crate directory and Rust reports wasm32-unknown-unknown as installed. Do this before debugging gameplay code.

2. Split rules from the window#

src/sim.rs defines Body and Run. It imports no graphics, browser or file APIs. Body contains position and velocity; Run contains ship, rocks, core position, score, lives, clocks and state flags.

#[derive(Clone, Copy, Debug)]
pub struct Body {
    pub x: f32,
    pub y: f32,
    pub vx: f32,
    pub vy: f32,
}

A struct groups named fields. pub makes them accessible to the sibling renderer module. f32 is a 32-bit floating-point number. Deriving Copy lets a small Body value be duplicated by value; the Vec of rocks instead belongs to Run and owns its allocated storage.

Run::new constructs a fresh starting game. It creates six rocks with deterministic positions/velocities, puts the ship in the centre, and sets ten cargo as the goal. The core path after each pickup is also deterministic. You can reproduce a run while learning instead of chasing random behavior.

Why separate files? A test can create a Run, feed inputs/time into tick and inspect results without opening a window or compiling the browser. That feedback is faster and sharper than judging a screenshot alone.

3. Borrow state and advance time#

The central method takes mutable access to one run:

pub fn tick(&mut self, dt: f32, direction: (f32, f32), dash: bool)

&mut self means the method may change this existing Run. direction is a tuple containing horizontal/vertical intent; dash is a boolean request for this tick. The function returns early when paused or over, preserving frozen rules.

It clamps dt to at most 0.05 seconds. This prevents a long background-tab delay causing a huge movement jump, at the cost of letting game time advance more slowly during severe stalls. This is a simple arcade policy, not a fixed-step or wall-clock-accurate simulation. A future competitive timer should use a deliberate real-time policy.

Countdown, dash cooldown and shield time all subtract dt and clamp at zero. Use seconds consistently. Confusing milliseconds with seconds would make a two-second cooldown either effectively instant or painfully long.

Checkpoint: read the pause test in sim.rs: calling tick while paused leaves the countdown unchanged. The production function, not a duplicate test implementation, is what the test calls.

4. Normalize motion and implement a dash#

Direction is normalized before speed is applied:

let length = direction.0.hypot(direction.1).max(1.);
self.ship.x += direction.0 / length * speed * dt;
self.ship.y += direction.1 / length * speed * dt;

Without normalization, holding two directions gives a vector longer than holding one, so diagonals move faster. max(1) avoids division by zero and preserves inputs smaller than one. The complete source also clamps the resulting ship centre inside arena bounds.

Normal speed is 190 units/second. A ready dash sets cooldown to two seconds and shield to a quarter second. While cooldown is above 1.75, movement speed becomes 540. That uses one countdown to represent a short active burst followed by recovery. Holding Space does not repeatedly trigger it: main.rs sends is_key_pressed, an edge event.

Try: move right, then diagonally; total travel speed should match. Dash across an empty stretch and watch DASH decrease. Press Space during cooldown; it should not restart the burst.

5. Move hazards, resolve damage and collect cargo#

Every rock advances by velocity times dt. Crossing an arena edge reverses the relevant velocity component and clamps the rock inside the boundary. This is intentionally simple bouncing-circle gameplay, not a rigidbody engine exercise.

Distance checks compare the ship centre with rock/core centres. A rock hit spends one life, returns the ship to centre and grants 1.5 seconds of protection. The early return after the last life prevents unsigned lives from being decremented below zero. The shield also makes short dash-through maneuvers possible.

A core pickup advances score, adds two seconds and chooses the next deterministic position. Ten cores set won and over. Zero remaining time sets over without won. The renderer reads these flags; it does not recalculate win conditions independently.

Checkpoint: test a protected overlap, then an unprotected overlap. One collision should cost one hull point and provide recovery time rather than consuming all lives in adjacent frames.

6. Test without a browser#

From your project folder:

rustc --test src/sim.rs -o /tmp/salvage-tests
/tmp/salvage-tests

The Windows equivalent uses a local output path such as salvage-tests.exe. This invocation uses only Rust's standard test support; it does not need the graphics dependency or the wasm target.

The included tests check normalized diagonal movement, pause/timeout, ten-core victory, dash activation, damage grace and life exhaustion. A test can clear the rock vector or put the ship on a core to target one branch. These are controlled scenarios, not secret cheats in the player build.

When a test fails, inspect the assertion's expected behavior before changing constants. For example, if pause consumes time, the bug is the early-return policy, not the HUD's rounding.

Exercise: write a test that starts with one life and zero shield, overlaps a rock, and verifies over=true with lives=0. That pattern is already represented in the full source; reproduce it yourself before comparing.

7. Connect macroquad drawing and keyboard input#

main.rs imports macroquad through the engine dependency and declares mod sim. The async game loop creates a Run, reads keys, calls tick, draws the current state, then yields with next_frame().await.

if is_key_pressed(KeyCode::R) {
    run = Run::new();
}
if is_key_pressed(KeyCode::P) && !run.over {
    run.paused = !run.paused;
}

Rust assignment replaces the whole run on restart. ! negates a boolean. Pause input lives outside tick, so it can still unpause while tick returns early. This solves the same paused-update trap discussed in the JS tutorials.

A camera maps an 800×600 logical arena into a centred viewport, maintaining its aspect ratio when the browser size changes. Drawing uses the same units as simulation. The ship is a triangle, rocks are polygons, cargo is a pulsing circle and the HUD uses text. The cargo's cosmetic pulse uses wall time even while rules are paused; only the run state freezes.

The overlay reads paused/over/won to choose its message. There is no second copy of the rules hidden in draw code. The native entry point calls macroquad::Window::from_config rather than using the macro attribute, matching Nord's existing direct-macroquad examples.

8. Build and Play in Nord#

Save both Rust files. Use Build Rust and inspect compiler output in Console; Play builds the Rust project before running its dev page. From an engine checkout, the explicit commands are:

nord build-rust examples/rust-salvage
nord serve examples/rust-salvage

For an extracted project use its own directory path instead. Open the printed URL, click the canvas to focus, then try WASD, Space, P and R. Editing Rust requires recompilation; JS hot reload does not patch compiled WASM instructions.

If the page cannot find target/web/game.wasm, run Build Rust first. If Cargo cannot find nord-runtime-wasm, fix the dependency path. If it needs the registry while offline, ensure the locked crates are cached. The existing macroquad bundle may report the repository's documented harmless register_plugin error from unused quad_net code; unrelated errors are not covered by that exception.

9. Export an actual standalone WASM game#

From the project parent directory:

nord build rust-salvage --target web-wasm-game --out salvage-web --zip
python3 -m http.server 8003 --directory salvage-web

The exporter compiles a release game.wasm, copies the vendored macroquad JS loader and writes an index.html with relative paths. It supplies the required wasm linker setting through Nord's Rust pipeline. A plain manual cargo command is not a replacement for all exporter setup.

Open http://localhost:8003. In Network, verify a .wasm file is fetched. Test a normal move, dash, pause/resume, loss, ten-core win and restart in this exported copy. Upload the whole folder or zip. wasm-bindgen is needed for some other Rust app targets, but not this macroquad game.

This sample's generated source has no external art or sound and no API server. Its web export can run without the local Rust toolchain. Circuit Vault's separate Node backend is a different deployment requirement, not a requirement of WASM games in general.

Advanced extensions: use a fixed-step accumulator; add deterministic seeds; serialize a replay as input/time records; add controller support; replace the circle-distance rules with Nord's scene/Script/rapier tier if your design needs scene-authored physics. Introduce one change with a test rather than mixing rendering, network and collision changes at once.

Complete source#

The complete Rust renderer and simulation follow, including the production rule tests. Cargo configuration, lockfile, project metadata and dev HTML are also included; the source archive excludes compiled target files and includes the licence. Update its engine path when extracting outside the repository, then use Nord's build/export workflow above.

src/main.rs#

use nord_runtime_wasm::macroquad::{self, prelude::*};
mod sim;
use sim::Run;

async fn game() {
    let mut run = Run::new();
    loop {
        if is_key_pressed(KeyCode::R) {
            run = Run::new();
        }
        if is_key_pressed(KeyCode::P) && !run.over {
            run.paused = !run.paused;
        }
        let axis = |positive, negative| {
            (if is_key_down(positive) { 1. } else { 0. })
                - (if is_key_down(negative) { 1. } else { 0. })
        };
        run.tick(
            get_frame_time(),
            (axis(KeyCode::D, KeyCode::A), axis(KeyCode::S, KeyCode::W)),
            is_key_pressed(KeyCode::Space),
        );
        // Fit a fixed logical arena into the window; resizing does not change the rules.
        let scale = (screen_width() / 800.).min(screen_height() / 600.);
        let (w, h) = ((800. * scale) as i32, (600. * scale) as i32);
        let camera = Camera2D {
            viewport: Some((
                ((screen_width() as i32 - w) / 2),
                ((screen_height() as i32 - h) / 2),
                w,
                h,
            )),
            target: vec2(400., 300.),
            zoom: vec2(2. / 800., 2. / 600.),
            ..Default::default()
        };
        set_camera(&camera);
        clear_background(Color::from_rgba(8, 13, 30, 255));
        for i in 0..70 {
            let x = (i * 137 % 800) as f32;
            let y = (i * 97 % 600) as f32;
            draw_circle(x, y, 1., DARKGRAY);
        }
        draw_rectangle_lines(15., 55., 770., 530., 2., DARKBLUE);
        let pulse = 1. + (get_time() as f32 * 5.).sin() * 0.15;
        draw_circle(run.core.0, run.core.1, 12. * pulse, GOLD);
        for r in &run.rocks {
            draw_poly(r.x, r.y, 6, 18., r.x, Color::from_rgba(160, 70, 130, 255));
        }
        let color = if run.shield > 0. { SKYBLUE } else { WHITE };
        draw_triangle(
            vec2(run.ship.x, run.ship.y - 15.),
            vec2(run.ship.x - 12., run.ship.y + 12.),
            vec2(run.ship.x + 12., run.ship.y + 12.),
            color,
        );
        draw_text(
            format!(
                "SALVAGE {}/10  HULL {}  TIME {:.0}  DASH {:.1}",
                run.score,
                run.lives,
                run.remaining.ceil(),
                run.dash
            ),
            20.,
            30.,
            25.,
            SKYBLUE,
        );
        draw_text(
            "WASD fly | Space dash | P pause | R restart",
            20.,
            595.,
            19.,
            GRAY,
        );
        if run.paused || run.over {
            draw_rectangle(100., 220., 600., 130., Color::from_rgba(10, 20, 40, 240));
            let title = if run.paused {
                "PAUSED - P resumes"
            } else if run.won {
                "CARGO SECURED! R plays again"
            } else {
                "SHIP LOST - R retries"
            };
            draw_text(title, 120., 285., 30., GOLD);
        }
        next_frame().await;
    }
}
fn main() {
    macroquad::Window::from_config(
        Conf {
            window_title: "Orbital Salvage".into(),
            window_width: 800,
            window_height: 600,
            ..Default::default()
        },
        game(),
    );
}

// Pure rules: no renderer, browser, file system or frame clock required.
#[derive(Clone, Copy, Debug)]
pub struct Body {
    pub x: f32,
    pub y: f32,
    pub vx: f32,
    pub vy: f32,
}
#[derive(Debug)]
pub struct Run {
    pub ship: Body,
    pub rocks: Vec<Body>,
    pub core: (f32, f32),
    pub score: u32,
    pub lives: u32,
    pub remaining: f32,
    pub dash: f32,
    pub shield: f32,
    pub won: bool,
    pub over: bool,
    pub paused: bool,
}
impl Run {
    pub fn new() -> Self {
        Self {
            ship: Body {
                x: 400.,
                y: 300.,
                vx: 0.,
                vy: 0.,
            },
            rocks: (0..6)
                .map(|i| Body {
                    x: 80. + i as f32 * 110.,
                    y: 80.,
                    vx: 35. + i as f32 * 8.,
                    vy: 45.,
                })
                .collect(),
            core: (520., 300.),
            score: 0,
            lives: 3,
            remaining: 60.,
            dash: 0.,
            shield: 1.,
            won: false,
            over: false,
            paused: false,
        }
    }
    pub fn tick(&mut self, dt: f32, direction: (f32, f32), dash: bool) {
        if self.over || self.paused {
            return;
        }
        let dt = dt.clamp(0., 0.05);
        self.remaining = (self.remaining - dt).max(0.);
        self.dash = (self.dash - dt).max(0.);
        self.shield = (self.shield - dt).max(0.);
        let mut speed = 190.;
        if dash && self.dash == 0. {
            self.dash = 2.;
            self.shield = 0.25;
        }
        if self.dash > 1.75 {
            speed = 540.;
        }
        let length = direction.0.hypot(direction.1).max(1.);
        self.ship.x = (self.ship.x + direction.0 / length * speed * dt).clamp(18., 782.);
        self.ship.y = (self.ship.y + direction.1 / length * speed * dt).clamp(55., 582.);
        for rock in &mut self.rocks {
            rock.x += rock.vx * dt;
            rock.y += rock.vy * dt;
            if rock.x < 15. || rock.x > 785. {
                rock.vx = -rock.vx;
                rock.x = rock.x.clamp(15., 785.);
            }
            if rock.y < 55. || rock.y > 585. {
                rock.vy = -rock.vy;
                rock.y = rock.y.clamp(55., 585.);
            }
        }
        if self.shield == 0.
            && self
                .rocks
                .iter()
                .any(|r| (r.x - self.ship.x).hypot(r.y - self.ship.y) < 29.)
        {
            self.lives -= 1;
            self.shield = 1.5;
            self.ship.x = 400.;
            self.ship.y = 300.;
            if self.lives == 0 {
                self.over = true;
                return;
            }
        }
        if (self.core.0 - self.ship.x).hypot(self.core.1 - self.ship.y) < 26. {
            self.score += 1;
            self.remaining += 2.;
            self.core = (
                80. + (self.score * 137 % 640) as f32,
                90. + (self.score * 91 % 450) as f32,
            );
            if self.score == 10 {
                self.won = true;
                self.over = true;
            }
        }
        if self.remaining == 0. {
            self.over = true;
        }
    }
}

mod tests {
    use super::*;
    #[test]
    fn diagonal_speed_is_normalized() {
        let mut a = Run::new();
        let mut b = Run::new();
        a.tick(0.01, (1., 0.), false);
        b.tick(0.01, (1., 1.), false);
        assert!(
            ((a.ship.x - 400.).hypot(a.ship.y - 300.) - (b.ship.x - 400.).hypot(b.ship.y - 300.))
                .abs()
                < 0.001
        );
    }
    #[test]
    fn pause_and_loss_freeze_rules() {
        let mut g = Run::new();
        g.paused = true;
        g.tick(0.05, (1., 0.), true);
        assert_eq!(g.remaining, 60.);
        g.paused = false;
        g.remaining = 0.001;
        g.tick(0.01, (0., 0.), false);
        assert!(g.over && !g.won);
    }
    #[test]
    fn ten_cores_win_and_dash_recharges() {
        let mut g = Run::new();
        g.rocks.clear();
        g.tick(0.01, (1., 0.), true);
        assert!(g.dash > 1.9);
        for _ in 0..10 {
            g.ship.x = g.core.0;
            g.ship.y = g.core.1;
            g.tick(0.01, (0., 0.), false);
        }
        assert_eq!(g.score, 10);
        assert!(g.over && g.won);
    }
    #[test]
    fn damage_has_grace_and_no_underflow() {
        let mut g = Run::new();
        g.shield = 0.;
        g.rocks = vec![g.ship];
        g.tick(0.01, (0., 0.), false);
        assert_eq!(g.lives, 2);
        g.tick(0.01, (0., 0.), false);
        assert_eq!(g.lives, 2);
        g.lives = 1;
        g.shield = 0.;
        g.rocks = vec![g.ship];
        g.tick(0.01, (0., 0.), false);
        g.tick(0.01, (0., 0.), false);
        assert_eq!(g.lives, 0);
        assert!(g.over);
    }
