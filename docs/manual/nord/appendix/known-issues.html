Fixed#

  • BUG-015 [fixed] Full-tutorial audit edge cases: Paper Worlds portfolio export changed </dollar replacement tokens; rapid 3D requests could race library readiness or retain stale scenes; off-road racer drag accelerated a stationary car; same-frame shooter death/boss hits could yield conflicting results; Ready could reset a live battle. Lossless embedding, shared load promises/scene request ownership, zero-speed drag, exclusive outcome checks and live-round rematch rejection now have focused regressions. Hardware/native verification limits below still apply.
  • BUG-014 [fixed] Restarting a paused scene kept it paused and retained input, elapsed time/timeScale and Persist run state. restart() now rebuilds cloned saved scene data, resumes and resets time/input, drops Persist state unless explicitly preserved, and coalesces concurrent calls. Unit regressions cover lifecycle/scheduler/cache isolation, Persist reset/opt-in and saved-score retention. Existing copied projects need Upgrade runtime.
  • BUG-013 [fixed] Babylon imported GLB material colours were overwritten by the default mesh material because imported meshes did not retain their own material reference. Model creation now records it before material application. Vector Patrol's real Blocksmith model palette regression fails on the old code and passes after the fix.
  • BUG-012 [fixed] Restarting an Arcade tilemap scene retained destroyed layers in the physics collision list, causing a browser tileWidth exception and freezing the new run. Tilemap teardown now unregisters its layers before destroying them. T33 browser regression wins/retries, then requires the restarted timer to advance through another loss and retry without browser errors.
  • BUG-011 [fixed] 2D palette drag/drop bypassed active-layer visibility/lock checks, allowing item placement into protected layers. Drop now rejects the operation before selecting an asset or mutating the map; locked and hidden layer regressions pass. Native drag interaction still needs an owner check.
  • BUG-010 [fixed] Fast 2D map load/reopen could fit before ResizeObserver measured the canvas, producing NaN view coordinates and preventing every placement click. Fit now measures current bounds and defers zero-size layouts. Separately, 2D demo Items → Brush wrote terrain instead of adding items; dragging palette cards did nothing, and generic sprite cards lacked dungeon/tank behavior. Item-context Brush now stamps configured project items, supports drag/drop and grouped stroke undo, and keeps script/body values. Two Floors new rats are verified through save/reopen and F5. Reopen already-open projects to load changed editor modules.
  • BUG-009 [fixed] Assets folder tree snapped back to a narrow width and file tiles descended in a staircase. Disabled tree scroll-area auto-shrink; paint thumbnails/icons without advancing the already allocated cell's layout cursor. Headless regressions verify retained divider width and aligned/wrapped rows at 48/84/160 px. Native pointer interaction in the rebuilt app remains unverified.
  • BUG-007 [fixed] macOS child webviews were vertically mirrored, covering the game header/console. wry 0.50 assumes an unflipped NSView but winit 0.30 supplies a flipped view; bounds now compensate. Reproduced and verified in the packaged editor with Noom on macOS, plus geometry regression at multiple zooms.
  • BUG-008 [fixed] Selecting an entity silently inserted missing component/script defaults and dirtied the scene. Inspector now displays defaults locally and writes only fields the user edits; regression opens Noom and verifies an unchanged scene/undo stack.
  • BUG-003 [fixed] Toolbar Export was permanently disabled despite the implemented export dialog; click regression now dispatches Export.
  • BUG-004 [fixed] Embedded views reappeared above menus/dialogs because end_frame overrode set_visible(false); frame visibility now honors overlays, including newly opened popups and recovery/desktop dialogs.
  • BUG-005 [fixed] Changing themes during Play could restore stale colors after Stop; the tint base is reset when applying a theme.
  • BUG-006 [fixed] Packaged hub omitted starter templates; build.sh now ships templates/ alongside examples/.
  • BUG-002 [fixed] macOS project locks misidentified live foreign-user processes as stale because kill -0 returned EPERM. The macOS check now reads ps -p PID -o pid=; the existing exclusivity regression covers pid 1.
  • BUG-001 [fixed] Rebuilt app examples showed old art/code — the hub reused persistent private copies under ~/.config/nord/examples/. USE CACHED CONTENT now defaults OFF: current example files open directly and old Recent/launch paths resolve to the current bundle. Opt-in ON retains saved copies for testing. Regression replaces an example asset then reopens it and verifies the new bytes; server regression verifies no-store and new bytes at the same URL.

Unverified / risks#

  • RISK-010 (M9, owner action) Desktop shell parts that are not verified on macOS/Windows: native menu bar, tray icon, global shortcuts, dock badge/taskbar progress (HostCommand::Badge/Progress: badge macOS only, progress via tao), context menus on Windows/Linux (only macOS popup is wired), app.autostart (LaunchAgent/registry/.desktop writers), file-association/URL-scheme registration (Info.plist keys generated; Windows register.reg needs the install path edited), rfd/notify-rust/arboard backends. Linux (webkit2gtk under Xvfb) runs the IPC/files/store/server smoke test in CI; Windows cargo check of the shell passes, macOS cannot be checked here. CI runs tools/player-smoke.mjs on macOS/Windows as non-blocking steps. Wayland: tray/global shortcuts compositor-dependent.

  • RISK-011 (M9) Permission manifest = application-level guard, not an OS sandbox (no App Sandbox/security-scoped bookmarks yet: picked paths are only remembered for the current run). Dialogs/process.run/http.fetch run on the UI thread in the native player (a slow call blocks the window; the page itself is not blocked). dialog.open in the browser fallback copies the chosen file into virtual app data. Clipboard images are unsupported natively. Markdown code fences are not syntax-highlighted in the code editor (CodeMirror codeLanguages not in the vendored bundle).

  • RISK-012 (M8) Windows x64 editor/CLI/player now cross-build with ./build-win.sh on macOS, with complete resources and zipped manual verified during packaging. Native MSVC release CI is required (no longer an optional Windows job); actual Windows GUI/hardware verification remains pending. macOS notarisation steps remain untested.

  • RISK-001a (M3-07 owner action needed) The webview feature compiles (type-checked against wry's Linux backend; the macOS build runs in CI macos-14) but embedding was never run on macOS. Checklist on the M1 Max: ./run.sh examples/conformance-2d → (1) Scene tab shows the 2D view in the panel rect, (2) resize the window/split → view follows, (3) Retina scale correct (no 2× offset), (4) click inside the view then press W/E/R/Cmd+Z → editor reacts (keys are forwarded), click back in egui → shortcuts work, (5) open a menu / Cmd+K → the webview pauses (placeholder) and returns, (6) ▶ Play shows the game in the Game tab, Stop clears it. If anything is off use ./run.sh --no-webview (Open in browser fallback; protocol identical). On Linux the webview is not wired (needs GTK loop) — macOS only for now.

  • M3 editor verified here: egui_kittest (12 headless UI tests), Xvfb + software GL smoke run (splash → hub → project), Playwright for the viewport protocol/picking/drag/snap/gizmos/thumbnails/log bridge. Not verified: window-geometry restore (needs a window manager), drag-and-drop of OS files/asset→hierarchy with a real pointer, Retina rendering, IME input in the code editor (text is applied by our own key handler; composition events are left to egui).

  • RISK-006 nord-player window shell (--features shell: wry+tao) cannot be compiled in the Linux sandbox (needs webkit2gtk/gtk); only its pure parts (serve, manifest, game-dir lookup) are unit-tested. macOS CI builds it and assembles Playground 3D.app; owner must run a bundled game once (window size, nord:// module scripts, audio, Cmd+Ctrl+F). bundle-mac layout/plist/icns are tested on Linux; codesign/dmg only run on macOS.

  • Export: --optimize is lossless PNG + WAV→MP3 only (no atlas packing / quantise → M4-11). Single-file builds keep UI fonts as sibling files. Vendored libs contain unused default CDN strings (Babylon); the offline check scans project-owned files + runtime only.

  • Code editor limits: multi-cursor covers typing/delete/enter/tab/arrows only (no word-wise moves, comment toggle or auto-close with several cursors; undo clears extras), tokenizer is not a parser (regex literals / nested template strings can mis-colour), formatter = re-indent by bracket depth (+ JSON pretty-print), squiggles only for JS (node --check, needs Node on PATH) and JSON; Rust errors surface via the Console (cargo check) and are click-to-open. Ligatures are stored in the skin but not drawn (egui has no shaping).

  • Viewport editing moves/rotates/scales the first selected entity only (multi-select is selection-only); parent rotation/scale are handled in 2D, 3D gizmos rely on Babylon's local/world handling (unparented entities verified).

  • Model thumbnails need the 3D edit view to be connected (they are rendered there); in 2D projects models show an icon.

  • nord-serve instances started by the editor keep running until the editor exits (one per opened project in a session).

  • Examples open current engine/bundle files by default; their saved private copies under ~/.config/nord/examples/ are used only with Settings → USE CACHED CONTENT ON. See EDITOR_UI.md.

  • RISK-001 egui + wry child-webview embedding on macOS (z-order, keyboard focus, egui popups over the webview, HiDPI sizing) cannot be tested in the Linux sandbox; verify on macOS CI / M1 Max. Spike first (M3-07).

  • RISK-002 Babylon Havok needs wasm served with application/wasm; some static hosts misconfigure → provide JS fallback (cannon-es) or inline base64 in single-file mode.

  • RISK-003 file:// loading blocks fetch/ES modules in browsers → single-file/file-safe export mode required (EXPORT_TARGETS).

  • RISK-004 Vendored Babylon (and Phaser banner comments) contain default CDN/asset URLs (e.g. cdn.babylonjs.com, assets.babylonjs.com) used only when a feature is left unconfigured (VR button, blue-noise, loaders' default asset roots). nord check-offline flags them, so it is a gate for project/build output (M4 must set Babylon Tools.*Url/disable those paths and allowlist the rest), not for vendor/.

  • M1 verified on Linux only: nord serve (incl. SSE reload endpoint wiring, HTML injection), new, check, thumbs, check-offline, vendor --verify. CI macos-14 job is untested until first push runs. SSE reload was not exercised in a real browser yet (M2 e2e). rustup wasm32 target is not installed in this sandbox (needed from M5).

  • M2 core: attachDom and virtualJoystick (DOM code) have no tests yet — covered by the Playwright harness (M2-18). Prefab overrides format is: deep-merge onto the prefab root entity; an object with numeric keys patches an array by index (e.g. {"scripts":{"0":{"attributes":{"speed":7}}}}). Entity.worldPos ignores parent rotation (backends handle rotation natively).

  • M2 runtimes (verified headless Chromium/SwiftShader on Linux only; not yet on macOS/WKWebView or a real GPU): Phaser 4.2.1 arcade+matter, Babylon 9.30 + Havok. Notes: (a) Havok collision events only fire reliably when the scene steps physics, so Babylon physics uses Babylon's 60 Hz sub-step accumulator and results are copied back after each step (script fixedUpdate runs before it, in the same frame). (b) Havok disablePreStep is on by default — script-set transforms are pushed to the body for one step via teleported() and velocity is zeroed. (c) isGrounded/raycast ignore only skips the first hit (Havok returns the closest hit). (d) Phaser tilemaps are static world-space layers (not moved with their entity). (e) Phaser arcade bodies need entities without a rotated/scaled parent chain to be exact. (f) Hot reload does not re-fetch modules a script imports. (g) Software-GL e2e runs Babylon at ~4 fps so timings in tests are generous.

The console strip is now laid out from a stored height before the webview is allocated, so overlap should be impossible by construction; if the console still hides behind the game, report it.

tests/ui.rs panels share one process-wide NORD_CONFIG_DIR (recent projects, settings), so hub_search_opens_examples_and_docs_without_a_project failed when tests ran in parallel (it already failed at the start of M10, commit 0bf20cd1). Web editor (M11)#

  • Verified only in Chromium (headless via Playwright, plus the Claude desktop in-app browser for the first spike). Not verified: Safari, Firefox, Windows Edge, mobile browsers (M11-16, owner). Service workers need https or http://localhost.
  • Docker image / compose / systemd unit / nginx / Caddy files are written but not run (no Docker daemon in the development environment). CI job web-editor is written but has not run on GitHub yet.
  • Browser export has no minify / single-file / optimise / event-sheet compile (need Node/ffmpeg) and no Rust/WASM or app-bundle targets; it runs on the page thread, so the page is busy for a few seconds. Thumbnails, phone preview, the node --check JS lint and Rust builds are desktop-only (they need threads/processes).
  • Browser storage is per-origin and can be cleared by the browser: download a zip for a safe copy. Large projects live in memory (the project tree is held in the wasm heap).
  • Server mode: single writer per project (45 s lock, refreshed every 15 s); a second session is read-only. No real-time co-editing; remote changes by other sessions are not pushed into an open editor (SSE exists, the client does not consume it yet). A failed upload is retried every 1.5 s while the server is unreachable. Deleting/renaming while the server is down is not replayed — reload to resync.
  • Server jobs run the nord CLI as the server's own user with a time limit only; CPU/RAM limits come from the container/systemd unit, not from the server process. --allow-rust-jobs executes project build scripts: container only.
  • The web editor cannot open a folder from disk (browsers have no folder path): use zip import. The File System Access API folder mode from the plan is not implemented.
  • Pre-existing, not from M11: cargo clippy --workspace --all-targets -- -D warnings reports 5 lints in nord-editor and 1 in a nord-export test; cargo fmt --check differs in several files.

Not verified / limits:
  • Mouse capture uses Pointer Lock. macOS WKWebView main Play and FPS Test acquisition, Esc release, Resume recapture and Shift+Esc Test stop verified natively on 2026-10-21 after adding the missing host callback. The isolated WebKit SPI compatibility shim may need revisiting after OS/Wry updates. Right-drag fallback remains for unsupported hosts; Windows WebView2 capture remains unverified.

  • Characters are blocky procedural models (walk/aim/death animation only); no skinned glTF animation. Weapons are procedural view models without reload art beyond a dip.
  • Physics is custom: circle-vs-AABB collision, step-up 0.46 m, no pushable props, no moving platforms/lifts, doors do not crush. Stairs need the cell above their top to have no floor on the upper layer.

  • No mid-level quick-save: checkpoints (a checkpoint pad) restore health/ammo/keys/position after dying, nothing else (enemies respawn).
  • Level size ≤ 256×256 cells; baking cost grows with vertices × lights in range (the demo level, 12k tris/21 lights, bakes in ~0.2 s; very large levels may take seconds).
