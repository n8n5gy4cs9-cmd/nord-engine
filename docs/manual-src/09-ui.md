The UI is what the player reads and clicks: score, health, menus and buttons. Nord’s DOM UI sits over the game view and works in 2D and 3D.

::: dummies
Use a label for text and a button for an action. Put health and score on the hud screen. A screen is a named group you can show or hide together.
:::

`game.ui` is a lightweight **DOM overlay** on top of the canvas — crisp text, accessible, CSS-themed. It works the same in 2D, 3D and plain HTML projects.
Widgets live on named **screens** (layers). `hud` always exists and is visible; create others for menus and show them on demand.

::: dummies
Imagine a sheet of see-through plastic laid over the game. You draw the score, buttons and menus on that sheet, and the game keeps running underneath.
:::

**File: your script, for example `scripts/Hud.js`** (the `start()` method)
```js
start() {
  const ui = this.ui;
  this.scoreLabel = ui.label('Score: 0', { x: 16, y: 16, size: 24 });                    // top-left by default
  this.hp = ui.bar(1, { x: 16, y: 56, w: 180, color: '#bf616a' });
  ui.menu('pause', [
    { text: 'Resume', onClick: () => { ui.hide('pause'); this.game.resume(); } },
    { text: 'Restart', onClick: () => this.game.restart() },
  ], { x: 200, y: 120 });
}
update() { this.scoreLabel.set(`Score: ${this.score}`); this.hp.set(this.health / 100); }
```
Positioning options for every widget: `x, y, anchor ('tl'|'tr'|'bl'|'br'), w, h, screen, style`.
Widgets: `panel`, `label`, `button`, `image`, `bar`, `menu`. Handles have `el` (the DOM node) and `remove()`; labels and bars add `set()`.

## UI scenes and the UI Designer (recommended)
The full guide with screenshots is the chapter [UI Designer](ui-designer.html).

Menus, HUDs and dialogs are best built as **data**, not code. Open the **UI Designer** tab, build the screen visually and save it as `ui/menu.ui.json`. Then load it:

```js
const menu = await this.ui.load('ui/menu.ui.json');   // plain HTML projects: createUI(root).load(...)
menu.on('play', () => this.game.restart());           // the button's Action name
menu.$('score').text = 'Score 12';                    // any node, by the name you gave it
menu.set('hp', 0.5);                                  // fills {hp} placeholders and bound bars
```

::: dummies
A UI file is a tree of boxes. A **vbox** stacks things top to bottom, an **hbox** left to right, and an **anchor** pins a box to a corner or the centre. Give a button an *Action* name; your code listens for that name. You never hunt for buttons in the page.
:::

* **Nodes:** panel, vbox, hbox, grid, center, scroll, label, button, image, bar, slider, input, checkbox, select, spacer, html, instance (another UI file inside this one).
* **Text:** labels support `{placeholders}`, `@translation.keys`, and safe rich text `[b] [i] [u] [color=#f7d89b] [size=28] [br]`.
* **Both directions:** UI → code with action names (also emitted as `ui:<action>` on `game.events`, so event sheets can react); code → UI with node handles (`text value checked visible disabled color index set() on() add() clear()`).
* **Themes:** a UI file can carry its own colours (`theme`), or inherit the project's skin and theme.
* **Fast:** each screen is one isolated shadow root; text is only touched when it changes.
* **Fallback:** the older `ui.label()/button()/menu()` calls and your own HTML keep working; use an `html` node for a custom corner.
* **3D world:** `game.gui.scene(def, { entity })` builds the same file as Babylon GUI floating over an entity.

* **Skins (one style for every button):** a skin file of rules named by type (`button`), class (`.danger`), id or descendants, with `extends`, `hover`/`pressed`/`disabled` states and `$tokens`. Apply it once with `ui.useSkin('ui/skin.json')`; swap it later to re-theme everything.
* **Images and 9-slice:** any node can take an `image` (`fit`, `cover`, `stretch`, `tile`, or `slice` with `[left, top, right, bottom]` borders in source pixels, like Unity's *Sliced* or Godot's NinePatchRect). The Designer has a drag-the-guides 9-slice editor and a Styles tab.

Full format and API: `docs/UI_SCENES.md`. Step by step: [T44 UI Designer](tut-t44-ui-designer.html); styles and 9-slice: [T45](tut-t45-ui-skins-9slice.html); a finished game using it: [T38 Coastline Sprint](tut-t38-coastline-sprint.html).

## UI as components
`uiPanel`, `uiLabel`, `uiImage`, `uiBar`, `uiButton` put the same widgets into the scene file so the **editor can lay them out**. A `uiButton` with `event: "start-game"` emits that name on `game.events` when clicked.

## Themes and skins
Project-level: `"ui": { "skin": "cyber", "theme": "tokyo-night" }`. A **skin** picks fonts, a **theme** picks colours (`--nord-*` CSS variables).
At runtime: `ui.setTheme({ theme: 'dracula', skin: 'cyber' })` or tweak single variables with `ui.theme({ accent: '#ebcb8b' })`.
The catalogue is in `assets/themes/themes.json` (editor and game share it). Fonts come from `vendor/fonts` — nothing is loaded from the internet.

## Ready-made screens (library)

## Touch controls
`virtualJoystick(input, parent)` (or the `ui-joystick` library script) drives your four direction actions and `input.stick`, so the same `axis`/`vec` code works on phones.

## In-world UI
* 2D: `text` component or damage-number script.
* 3D: `game.gui.worldLabel(entity, 'text')` follows an entity in screen space (Babylon GUI).
