A 3D scene needs something to look at and a camera to see it. Nord components create the models, materials and lights in Babylon for you.

::: dummies
Start with a box, a camera pointed at it and a light. Press Play before adding an imported model. If the box is missing, check the camera before changing the material.
:::

3D projects (`"type": "3d"`) run on Babylon.js with Havok physics. Units are metres, **y up, left-handed**; rotation is Euler degrees (XYZ).

::: dummies
3D is the same entity-and-component idea, plus a third direction: **y** is *up*, **z** is *forward*. A "mesh" is the shape,
a "material" is its paint, a "light" lets you see it.
:::

## Building blocks
* [`mesh`](component-mesh.html) — box, sphere, cylinder, capsule, torus, plane, ground. Perfect for greyboxing.
* [`model`](component-model.html) — a glTF/GLB. Models are instanced; animations are named clips (`play('walk')`).
* [`material`](component-material.html) — PBR: `color`, `metallic`, `roughness`, textures, `emissive`, `alpha`, `unlit`.
* [`light`](component-light.html) — directional (sun), point, spot, hemispheric (ambient sky). `castShadows` on a directional, point or spot light enables shadows for everything with `castShadow`. See *Lighting* below.
* [`skybox`](component-skybox.html) — cube map folder (`assets/skybox/day`, `sunset`, `night` ship with the engine).
* [`postProcess`](component-postProcess.html) — bloom, FXAA/MSAA, vignette, tonemap, grain.
* [`particles`](component-particles.html) — Babylon particle system with the same component name as 2D.

## Material assets

A `*.mat.json` file in `assets/` (Assets ▸ Create ▸ Material) is a shared material: `color, metallic, roughness, texture, normalMap, emissive, emissiveMap (a picture that glows), alpha, uvScale, uvOffset, doubleSided, unlit`. Select the file to edit it in the Inspector (with a quick preview), and point a `material` component's **asset** field at it; every mesh using it shares the values. Image import settings (Inspector on a selected image): **filter** `nearest` for crisp pixels and **wrap** `clamp`, stored in the sidecar `<image>.meta.json`.

## Cameras
A [`camera`](component-camera.html) entity creates a Babylon camera: `type: "orbit"` (follows `follow`, optional mouse control) or a free camera attached to the entity (first person: put the camera as a child of the player body).
Switch with `getComponent('camera').activate()`. Library: `fps3d.js`, `third-person3d.js`, `orbit-cam.js`, `fly-cam.js`, `rts-cam.js`.

## Animation
`model.play(name, { loop, speed })`. Clip names come from the glTF; `getComponent('model').animations` lists them. Blend by switching clips with short tweens on speed if you need to.
The Kenney pack in `assets/packs/kenney-platformer-3d/` has a rigged character to experiment with ([Assets](assets.html#optional-packs)).

## 3D UI
Use the DOM layer (`game.ui`, see [UI](ui.html)) for HUDs. For labels floating above entities, `game.gui.worldLabel(entity, 'Bob')` (Babylon GUI).

## Picking and rays
`game.physics.raycast(from, to, { ignore })` returns the first physics hit with the entity. The library has `interact-ray.js` and `physics-hitscan.js`.

## Performance tips
Reuse materials and models (instancing is automatic), keep shadow map size modest (1024 default), prefer one directional light with shadows, and use `postProcess` sparingly on laptops.
See [Performance](performance.html).

## Lighting (like Unity)
Lights work the same in 2D and 3D: add a `light` component to any entity, and the entity's **enabled** checkbox switches the light on and off.

| Field | Meaning (Unity name) |
|---|---|
| `kind` | `point`, `spot`, `directional` (sun, shines along the entity's forward direction), `hemispheric` (sky ambient) |
| `color`, `intensity` | Color, Intensity |
| `range` | 3D point/spot: the light fades out linearly to nothing at this distance (default 10). A point light with no range would light the whole world, so the default is 10 |
| `angle` | spot cone, degrees (default 30) |
| `radius` | **2D** lights: radius in pixels |
| `castShadows` | 3D: shadows from every mesh/model that casts shadows |
| `shadowStrength`, `shadowMapSize` | 3D: how dark shadows are (0-1) and the shadow map size (default from Quality) |
| `groundColor` | `hemispheric`: colour from below (sky colour above) |
| `offset` | 2D: move the light away from the entity centre |
| `flicker` | random brightness loss, 0-1 (2D and 3D) |
| sprite `lit` | 2D: untick on a sprite to draw it at full brightness (UI-like, ignores lights) |

Change lights from a script like any component: `this.entity.set('light', 'intensity', 3)`, also `color`, `range`, `angle`, and `radius` in 2D. A light is off when its entity, any parent, or the component is disabled. In the Scene view a **selected** light shows its shape (range sphere, spot cone, sun arrow in 3D; radius circle in 2D). 2D lights are all point lights; the model's `shadow` checkbox off means it does not cast shadows.

**Ambient light** is set per scene (`settings` in the scene file): `"ambient": "#202040"` and `"ambientIntensity": 1`. Intensity `0` turns ambient off (a pitch-dark scene lit only by your lights). 2D scenes without an `ambient` colour use a soft grey; 3D scenes without one have no ambient light except your own `hemispheric` lights.

**In the editor** the Scene view shows the scene's own lights and ambient, 2D and 3D. If the Scene view looks flat or too bright, check **Gizmos ▸ Scene lighting**: when it is off (or the scene has no light) you see neutral editor lighting. A light only changes the picture of objects whose material reacts to light: `unlit` materials and `emissive` colours do not change.

### Many lights, and which ones win
A material can use only a limited number of lights at once (**Lights per object** in the quality settings, 8 by default). Nord first limits every point/spot light to the objects inside its `range`, so a light far away costs nothing. If still more lights than the limit reach one object (a big ground plane under a whole city), the **strongest** ones (`intensity x range x range`) are used and the weakest are dropped from that object. If a light seems to do nothing, check that the object is inside its `range` and raise `range` or *Lights per object*.

### Quality settings (like Unity's Quality)
**Project ▸ Quality and lighting** (also in `nord.project.json` as `quality`). Pick a **level** (`low`, `medium`, `high`, `ultra`); a level is a preset, and you can change single values after it:

| Setting | low | medium | high | ultra |
|---|---|---|---|---|
| Shadows | off | hard | soft | soft |
| Shadow resolution | 512 | 1024 | 1024 | 2048 |
| Lights per object | 4 | 4 | 8 | 12 |
| Anti-aliasing (MSAA) | off | on | on | on |
| Render scale | 0.75 | 1 | 1 | 1 |
| Post-processing (bloom, tonemap, vignette) | off | on | on | on |

The same panel edits the open scene's **ambient colour and intensity** (Unity's Environment Lighting). 3D only: these quality settings are applied by the 3D (Babylon) runtime.

```json
"quality": { "level": "medium", "shadows": "soft", "maxLights": 8 }
```
