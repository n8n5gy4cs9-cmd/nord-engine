- 2026-10-24 — **Lit sprites like Unity's Sprite-Lit (colours blend).** Cause of "the second light does nothing / needs intensity 30": a flat sprite was lit like a 3D surface (angle to the light), so lights beside it barely counted, and raising the intensity just clipped everything to white. Sprites in 3D now use their own shader (`createSpriteMaterial` in `runtime/babylon/lighting.js`, game + Scene view): every point/spot light adds colour × intensity × falloff(range) per pixel, ambient/sun/hemispheric lights add flat, the sum multiplies the picture, so red + blue = magenta and intensity ~1 is normal. No lights in the scene = the picture as it is; `lit` off = always as it is. Tests: `tools/light-check` (red/blue blend, upright, far from origin), `tools/viewport-sprite-lights-test.mjs` (Scene view).

New `tools/light-check` cases: point light lights a sprite (bright under it, dark far away), light behind it, light off = dark, `lit:false` ignores lights (all 20 pass).

- 2026-10-24 — **Fix: model lights randomly stopped / ignored enable toggles.** Cause: models were created as GPU *instances* of the loaded model, and Babylon never refreshes an instance's light list, so a disabled ambient/sun light kept lighting the cube while its point light (limited to the instance by the range culling, not to the source mesh that is really drawn) was ignored. Now every `model` is a set of real meshes (runtime + editor Scene view), so light lists are always current.
