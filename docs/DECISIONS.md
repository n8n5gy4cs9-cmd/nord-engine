# Decisions (ADR log)

Append new decisions at the bottom. Format: context → decision → consequences. Status: accepted | superseded.

## ADR-001 Editor = Tauri v2 + web UI (PCUI), not egui — SUPERSEDED by ADR-013
**Context.** Owner asked "egui as engine or copy from examples, if better" and "use some better UI",
plus a *full code editor with CodeMirror, vendored*, thumbnails, docs with live code.
**Decision.** Editor UI is HTML/JS (PCUI from PlayCanvas editor, CodeMirror 6, Lucide icons) inside a
Tauri v2 shell with Rust backend. The viewport reuses Babylon/Phaser = true WYSIWYG.
**Consequences.** + CodeMirror native, + docs/tutorials in the same stack, + testable in Chromium,
+ Win/Linux bundles come free. − Not a "pure Rust" UI. egui is still used for the Rust **app** runtime (ADR-010).
Veto path: swap shell to eframe+wry; backend contract (ARCHITECTURE §4) stays.

## ADR-002 Three runtime tiers sharing one scene JSON — accepted
Phaser (2D JS), Babylon (3D JS), Rust/WASM (macroquad games, egui apps), plus a plain-HTML tier. Owner asked for
Phaser+Babylon vendored and for wasm+webgl. Conformance examples must run on every tier that supports them.

## ADR-003 Scripting = JavaScript first — accepted
JS scripts hot-reload instantly and are what the huge snippet library is written in. Rust scripts only for wasm tiers.
TypeScript optional later via vendored `typescript`/esbuild-wasm (not now).

## ADR-004 Everything vendored, no CDN — accepted
`vendor/` committed; offline scanner enforces. Fonts too (bundle Inter + JetBrains Mono, OFL).

## ADR-005 Upstream repos are harvested, not forked — accepted
`tools/fetch-upstreams.sh` makes shallow/sparse clones into gitignored `third_party/`; useful files are *copied* into
`library/`, `examples/`, `docs/`, `editor/` with attribution in `THIRD_PARTY.md`; `UPSTREAM.lock.json` records SHAs.
Do not vendor whole Godot (≈1 GB+). Godot/Defold **UIs are not reused**.

## ADR-006 PRD.json is the source of truth for tasks — accepted
`task.md` is generated by `node tools/tasks.mjs render`. Mark work with `node tools/tasks.mjs done <ID>`. CI/AI can
run `node tools/tasks.mjs check` to detect drift.

## ADR-007 No JS build step for editor/runtime — accepted
ES modules + import maps. Only exception: one-off bundles (CodeMirror) produced by `tools/vendor.mjs` with esbuild and committed.

## ADR-008 Mac wrapper via prebuilt player shell — accepted
Prebuilt `NordPlayer.app` (wry+tao) + resource swap (ARCHITECTURE §7). Avoids needing Xcode/Rust on the user's machine per game.

## ADR-009 Physics choices — accepted
2D: Phaser Arcade (fast, simple) + Matter (rich). 3D: Havok (`@babylonjs/havok`, wasm). Rust: rapier2d (rapier3d later).

## ADR-010 Rust/WASM: macroquad for games, eframe/egui for apps — accepted
macroquad: tiny wasm, WebGL1/2, audio, no wasm-bindgen needed. Bevy is reference/examples source only (large wasm; maybe an M8 template).
raylib: examples used as porting source for macroquad samples (raylib itself is C).

## ADR-011 Licences — accepted
Own code MIT. Vendored libs keep licences (Phaser MIT, Babylon Apache-2, CodeMirror MIT, PCUI MIT, Lucide ISC, rapier Apache-2,
macroquad MIT/Apache, egui MIT/Apache). Godot icons CC-BY-4.0 need attribution if used. **Defold ships a custom licence** (Apache-based
with extra terms) → inspiration only until reviewed. Re-verify each `LICENSE` at fetch time (`fetch-upstreams.sh` prints them).

## ADR-012 Platform strategy — accepted
Develop for aarch64-apple-darwin; use `camino`/`dirs`/`std::path` correctly, no hard-coded `/`. CI: `macos-14` (Apple Silicon) first;
Windows/Linux jobs added in M8 (allowed to fail until then).

## ADR-013 Editor = native Rust egui (eframe + egui_dock) + embedded wry viewport; no Tauri — accepted (owner decision)
**Context.** Owner prefers a native, lightweight Rust editor over a webview app, and asked for a full code editor.
Games are JS (Phaser/Babylon) so a webview is needed for viewport/preview regardless; Tauri only added a web UI shell.
**Decision.** `nord-editor` = eframe (wgpu/Metal) + egui_dock + egui_extras (images, SVG icons, syntect). The central viewport/Play/Docs
panel hosts a `wry` child webview (edit mode of the vendored runtimes), synced with egui over IPC (ARCHITECTURE §4). Code editor is native
(syntect highlighting + our own editing features); CodeMirror remains vendored only for the HTML manual's live examples.
Mac wrapper uses a minimal `wry`+`tao` `nord-player`.
**Consequences.** + fast, single Rust binary, native look, no web UI framework, easy cross-platform. − Must build a code editor on egui
(no multi-cursor/LSP initially); − wry-in-egui embedding quirks (spike in M3-07; fallback = separate wry window);
− editor UI tested via egui_kittest not Playwright. PCUI no longer vendored.

## ADR: Skins + themes are data (assets/themes/themes.json), dark only (2026-10-12)
A *skin* is a font pair (UI + code, ligatures on/off); a *theme* is a dark color set (UI colors + syntax colors). One JSON is the source for the JS runtime (generated module), the egui editor (`include_str!`) and the code editor. Light themes are deliberately not shipped for now. All fonts are vendored woff2 (OFL) — no CDN.
